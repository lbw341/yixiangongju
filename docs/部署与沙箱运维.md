# 部署与沙箱运维（Docker 全限制沙箱）

> 本文面向**接盘方运维人员**：把本平台部署到一台具备 Docker 的服务器上，供外部用户网页调用作者上传的工具。沙箱把每个工具脚本隔离在一次性 Linux 容器中运行（断网、限资源、非 root、只读输入、超时强杀），保证作者脚本无法危及宿主机与其它用户。

---

## 一、前置准备

### 1.1 选择部署主机

| 环境 | 说明 |
|------|------|
| Windows Server / Win10/11 | 安装 **Docker Desktop**，后端选择 **WSL 2**（生产推荐用 WSL2 而非 Hyper-V，避免许可证问题） |
| Linux (Ubuntu 20.04+) | 原生 Docker Engine，推荐长期运营使用 |

### 1.2 安装 Docker

- **Windows（Docker Desktop）**：下载安装 Docker Desktop，打开 Setting → Resources → WSL Integration，确保已启用。安装完成后 `docker version` 能输出版本号。
- **Linux**：`curl -fsSL https://get.docker.com | sh`（或用发行版源安装 docker.io / docker-ce）。

> 注意：沙箱要求 `--network none`，仅需本机 Docker 引擎，无需远程 Docker host 配 TLS。镜像构建与 `docker build` 需要联网拉取基础镜像，这是**部署时**的动作；沙箱运行期容器内没有网络，二者不冲突。

### 1.3 硬件建议

- 每并发一个沙箱容器约占用 512MB 内存 + 1 CPU（对应 `sandbox.memory` / `sandbox.cpus`）。按预计并发量放大：10 并发建议 ≥ 8GB 内存 / ≥ 12 核。

---

## 二、构建沙箱镜像

进入仓库根目录，执行：

```bash
docker build -t tool-sandbox:latest .
```

镜像内含：`bash`、`python3`、`node`、`jdk`（temurin 23）+ 容器 launcher `/usr/local/bin/launcher`，并创建非 root 用户 `sandboxuser`(uid 1000)。

验证：

```bash
docker run --rm --user 1000:1000 tool-sandbox:latest id -u   # 应输出 1000
docker run --rm --user 1000:1000 tool-sandbox:latest java -version
```

---

## 三、配置 `application.properties`

在 `backend-java/src/main/resources/application.properties` 中（已有默认值，按需调整）：

```properties
# Docker 全限制沙箱（生产必须开启；false 仅限本地开发显式关闭）
sandbox.enabled=true
sandbox.memory=512m
sandbox.cpus=1
sandbox.timeout=120
sandbox.docker-image=tool-sandbox:latest
sandbox.run-as-user=1000:1000
sandbox.launcher-container-path=/usr/local/bin/launcher
```

| 配置 | 含义 | 默认 |
|------|------|------|
| `sandbox.enabled` | 是否走 Docker 沙箱执行。**生产必须 `true`**；`false` 会直接以宿主机进程运行作者脚本，仅限本地开发调试 | `true` |
| `sandbox.memory` | 容器内存上限（Docker `--memory` 值，如 `512m`） | `512m` |
| `sandbox.cpus` | 容器 CPU 上限（Docker `--cpus`） | `1` |
| `sandbox.timeout` | 容器运行超时秒数，超时强杀（`destroyForcibly`） | `120` |
| `sandbox.docker-image` | 沙箱镜像名，必须与 `docker build -t` 的镜像名一致 | `tool-sandbox:latest` |
| `sandbox.run-as-user` | 容器内 UID:GID（非 root） | `1000:1000` |
| `sandbox.launcher-container-path` | 容器内 launcher 路径 | `/usr/local/bin/launcher` |

### 运行冒烟验证

用提供的交付冒烟脚本，在具备 Docker 的主机上从仓库根执行：

```bash
bash deploy/docker-run-smoke.sh
# Windows Git Bash / WSL2 下同样执行；脚本会自动用 cygpath 换算挂载路径
```

脚本会构建镜像，并对 **python / node / bash / java** 四类运行时逐一跑真实容器，断言：
1. I/O 契约：脚本 `argv[1]=/data`、数据文件经 argv 传入、`DATA_DIR / INPUT_FILES / RESULT_DIR` 三个环境变量正确；
2. 结果写回 `$RESULT_DIR/out.txt` 且宿主侧可读；
3. **断网**：`--network none` 下容器内 curl/wget/ping/getent 全部失败，但脚本自身正常；
4. **非 root**：容器内 `id -u` = 1000；
5. **超时强杀**：睡 60s 的脚本被外层 timeout 提前杀死，不长期挂起。

> **脚注：** 冒烟脚本 `deploy/docker-run-smoke.sh` 中的 docker 命令参数（包括挂载、环境变量、网络隔离等）是脚本自行手写的，并未调用 Java 服务的 `SandboxExecutionService` 来组装。因此，冒烟 PASS 仅验证"手写 argv 所描述的容器 + launcher + 挂载 + env 契约"正确，不能检测 Java 服务端 argv 组装逻辑是否与之对齐（例如 Java 端对 scriptDir 的推导方式可能不同）。生产环境仍需依赖 `SandboxExecutionService` 的单测覆盖。

## 四、启动平台

沿用现有部署方式（Spring Boot jar / `start.bat`）启动后端即可，前端已打进 `static/`。确认：

- MySQL 已就绪（`application.properties` 数据源指向正确）；
- 沙箱配置无误，`sandbox.docker-image` 与实际构建镜像一致；
- 运行账号需要有执行 `docker` 命令的权限（`docker ps` 可通）；生产建议后端进程与 docker 用户组一致。

## 五、安全边界与运维要点

### 5.1 沙箱强制项（不得关闭）

| 项 | 说明 |
|----|------|
| 断网 | `--network none`，容器内无法访问任何网络；依赖（pip/npm）必须在**上传时**于宿主机预装，不入容器 |
| 资源限制 | `--memory` / `--cpus` 限制单容器占用 |
| 非 root | `--user 1000:1000`，容器内无 root 权限 |
| 只读输入 | `/data`（输入）、`/script`（脚本）只读挂载，脚本无法篡改输入 |
| 超时强杀 | 超过 `sandbox.timeout` 秒即 `destroyForcibly` |
| 结果单向回传 | 仅 `/result` 目录（可写）+ stdout 被取回，输入目录不会回流宿主 |

### 5.2 已知限制（当前版本，后续版本将补齐）

> 以下限制与部署无关，但影响工具作者的脚本能力，务必在交付说明中告知作者：

1. **python venv 暂未挂载进容器**（已延期：此为原计划 Task 5 Step 1 承诺的 venv 挂载能力的正式偏差，非仅已知限制）：作者在宿主机用 `requirements.txt` 制作 venv 依赖，但容器内只提供系统 `python3`（无预装 pip 包）。若作者脚本依赖 pandas 等第三方库，需等后续版本将 venv 挂载进容器，或依赖上传期预装到镜像级 Python。
2. **java `lib/` 依赖目录暂未挂载进容器**：入口 jar 旁的 `lib/*.jar` 外部依赖目录尚未随 script 挂载，容器内仅存在入口 jar 单文件（`/script/<name>.jar`）。纯单 jar（无外部依赖）可正常运行；带 `lib/` 依赖的工具需要后续版本补充挂载。
3. **bat / cmd 运行时在 Linux 沙箱容器内不支持**：`bat` 是 Windows 专属运行时（依赖 `cmd.exe`），本镜像为 Linux 容器，容器内 launcher 对 `bat`/`cmd` 直接返回错误。`bat` 工具仅能通过**进程级回退**（`sandbox.enabled=false`，仅限本地/可信环境）或将来引入 Windows 容器运行。交付冒烟脚本也不包含 bat。

### 5.3 运维排障

| 现象 | 排查 |
|------|------|
| 工具执行报 "docker: command not found" | 后端进程无权调用 docker：确认 docker 已装且运行用户可执行 `docker ps` |
| 工具执行报镜像不存在 | `sandbox.docker-image` 未构建或名字不一致：`docker images` 对比 |
| 工具执行总是超时 | `sandbox.timeout` 过小；或脚本真的有长任务（调整时代见 5.1 资源/超时语义） |
| 工具执行 exit code 非 0 | 看返回的输出：脚本自身报错与沙箱拒绝（如 launcher 参数错误）会分开提示 |
| 容器内中文乱码 | python 脚本需以 UTF-8 输出；容器 locale 通常为 C.UTF-8 |

### 5.4 电子围栏之外的提示

- **生产环境必须 `sandbox.enabled=true`**。任何"为了让 bat 能跑/为了省事"而回退进程级的做法都会把作者脚本暴露在宿主机权限下，属高危操作。
- 建议给后端单独建操作系统账号，仅授予 docker 组权限，避免使用 root 运行后端。
